## 2. Architecture / build system

Static HTML generated by Python build scripts. Key files:

- `assets/data/tools.js` - `RAW_TOOLS` array = source of truth for the homepage grid, search, category counts. Each tool: `{ id, name, category, icon, premium, rating, usageCount, description, features, keywords }`. `slug` and `url` are DERIVED via `slugify(name)` (lowercase, non-alphanumerics -> hyphens). **The generated tool file MUST be named `tools/<slugify(name)>.html`** or the homepage link 404s.
- `tools_*.py` (e.g. `tools_developer.py`, `tools_batch1.py`) - tool page specs via `toolkit.tool(...)`. Collected by `build-tool-page.py` `TOOL_MODULES`.
- `toolkit.py` - helpers: `tool, ws, info, row, text_input, number_input, select, switch, textarea, status_line, buttons, HR, html_block, readonly, slider, color_input`. NOTE: `tool()` now auto-generates the SEO title as `Free {name} | 123MiniApps` (and og_title the same); the `title=` arg is ignored for the tag. `description` MUST be 100-175 chars (assert). FAQ template question is "Is my data private with {name}?" (offline claim already removed).
- `build-tool-page.py` - generates `tools/<slug>.html` from specs. `FURTHER_READING` dict maps tool slug -> (blog slug, blog title).
- `blog_posts_*.py` - blog article specs. Collected by `build-blog.py` `POST_MODULES`. POST block types: `('p',t) ('h2',t) ('h3',t) ('ul',[..]) ('ol',[..]) ('table',[headers],[rows]) ('callout',title,text) ('tool',slug,name,blurb) ('quote',t)`. POST fields: `slug, icon, nav_title, headline, title, standfirst, description, published, keywords, related_tools, body`.
- `build-css.py` - minifies `assets/css/*.css` -> `main.min.css`. **Minifier bug already fixed**: it must NOT strip spaces around `+` inside calc() (that broke the theme picker). Keep `+` out of the whitespace-collapse char class.
- `build-sitemap.py`, `build-llms.py` - regenerate `sitemap.xml` and `llms.txt` (both auto-scan; safe to run).
- `indexnow.py` - pings Bing/Yandex. Key file `76cd4323f3b048f7e5c46419eb98a9ea.txt` at root. Usage: `python3 indexnow.py --all` or `python3 indexnow.py tools/x.html blog/y.html`.
- Service worker `service-worker.js` - **network-only for HTML** (tools always online, never cached offline), stale-while-revalidate for assets. `VERSION` constant is the cache-bust version.
- Tests: `NODE_PATH=/tmp/testdeps/node_modules node test/run.js core` (jsdom). If missing: `mkdir -p /tmp/testdeps && cd /tmp/testdeps && npm install jsdom`. `test/phase-core.js` hardcodes the tool count (currently 101) - update it when count changes.

## 3. CRITICAL build rule: generate ONLY new pages, never a full rebuild

Running `python3 build-tool-page.py` (all) or `python3 build-blog.py` (all) REGENERATES every page and will REGRESS manual fixes that live only in generated HTML (e.g., em-dash cleanup) or differ from source. Always generate ONLY the new pages:

```python
# generate specific new TOOL pages
import importlib.util
spec = importlib.util.spec_from_file_location("btp", "build-tool-page.py")
btp = importlib.util.module_from_spec(spec); spec.loader.exec_module(btp)
import tools_batch2
for page in tools_batch2.PAGES: btp.build(page)   # writes only these
```

```python
# generate specific new BLOG pages (+ rebuild blog index so they list)
import importlib.util, os
spec = importlib.util.spec_from_file_location("bb", "build-blog.py")
bb = importlib.util.module_from_spec(spec); spec.loader.exec_module(bb)
posts = bb.collect_posts(); bb.compute_related(posts)
NEW = {"slug-a","slug-b"}
for p in posts:
    if p["slug"] in NEW:
        open(os.path.join(bb.BLOG_DIR,p["slug"]+".html"),"w",encoding="utf-8").write(bb.build_article(p))
open(os.path.join(bb.BLOG_DIR,"index.html"),"w",encoding="utf-8").write(bb.build_index(posts))
```

## 5. Conventions / gotchas (do not violate)

- **ASCII only. No em dashes (—) or en dashes (–) anywhere** - user strongly dislikes them; use hyphens/colons. This applies to tool copy, articles, robots.txt, llms.txt, everything served.
- **Title format:** `Free {name} | 123MiniApps` (auto in toolkit). og/twitter titles match.
- **New tools = `premium: True`** in tools.js when they have real depth; mark the Premium badge accordingly (don't over-use).
- **Category grouping** drives related-tools cross-linking (client-side from tools.js). Pick the right `cat`.
- **Count references:** when tool count changes, update hardcoded copy site-wide with careful phrase replacements (`"101 tools"`, `"101 Free"`, `"101 free"`, homepage title/hero/headings, footer, manifest, `test/phase-core.js`). PRESERVE unrelated numbers (e.g. "95-character keyboard set" in password articles). Then rebuild sitemap + llms.
- **Version bump** the cache version across files each deploy: `grep -rl "2\.8\.X" ... | sed -i 's/2.8.X/2.8.Y/g'` and the SW `VERSION`.
- **CSS classes that exist:** `.result-grid .result`, `.data-table`, `.workspace__row`, `.range`, `.btn .btn--primary .btn--ghost .btn--secondary .btn--sm`, `.switch/.switch__input/.switch__track/.switch__thumb`, `.info-panel`, `.field/.field__label/.field__hint`. `.segmented` does NOT exist (use `.btn` toggles).
